# Event media request links

Public link for Fall Brawl 6: https://tngos.tngboxinggym.com/events/2/media

Each event uses `/events/{event_id}/media`. Event Ticket Sales includes a Media Pass Requests panel for administrators and staff. Enable applications, copy the link or a share message for fighters, preview the public form, review pending/approved/declined requests, add private staff notes, and export the media list as CSV. Requests are closed by default until authorized staff enables the event; the initial Fall Brawl 6 link is enabled during deployment verification.

The mobile public form collects name, email, optional phone, outlet, media role, team size, optional website/social profile, coverage notes and fighter referral. A `?ref=Fighter%20Name` parameter can prefill the optional referral field. No login, browser storage, payment or gym membership is required. Request acknowledgement explicitly says the application does not grant admission.

Applicants receive an on-screen receipt only. Staff records approval and separately contacts the applicant to coordinate access and any venue/commission requirements. This feature does not issue QR tickets, admission credentials, government credentials, gym accounts, email or SMS. Copying a share message does not send it. Contact details are not enrolled into marketing.

Staff-only JSON/CSV routes require active admin/staff authorization and private no-store responses. Public metadata contains no applicant information and hides event details when applications are disabled. Public POST responses do not reveal application IDs or review status. Requests are unique per event and normalized email; duplicate submissions cannot overwrite saved contact details or staff decisions. A hidden bot field, database-backed per-peer rate limit, bounded input fields and spreadsheet formula escaping protect the intake/export workflow. Submitted links are stored for staff review and never fetched by the server.

Validation covers anonymous submission, no ticket/member creation, staff-only access, duplicate and review protection, disabled events, invalid inputs, bot handling, request limits, CSV safety, SQLite/PostgreSQL integration, a storage-restricted mobile browser, failed submission retry, and staff review/copy controls. Provider messages and real applicant submissions are not generated by verification.
